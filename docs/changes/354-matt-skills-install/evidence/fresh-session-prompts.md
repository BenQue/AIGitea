# #354 fresh session 固定提示词

两个 provider 用同一组问题。每个提示词在一个新启动的会话里单独发送，输出原样保存，不改写。
会话全程只读：不安装、不修改任何文件、不调用任何技能，除非该提示词明确要求。

期望值在 [spec](../spec-matt-skills-install-261008.md) 的两节 fresh session 表中，不写进提示词，
避免会话照着期望作答。

## P1 发现与来源

```text
这是一次只读检查。不要修改任何文件，不要调用任何技能。

1. 列出你在本会话中能看到的、来自 Matt Pocock skills 的全部技能名称，并给出总数。
   如果同一个名称有多个来源，每个来源各列一行。
2. 对 triage、pr、retro、implement-spec、resolving-merge-conflicts 这五个名称，分别回答：
   本会话中是否存在；存在的话，它的 SKILL.md 解析后的真实绝对路径是什么（跟随符号链接到最终文件）。
   用 shell 的只读命令核实路径，不要凭记忆回答。
3. 读取你在第 2 步找到的 retro 的 SKILL.md 所在快照或插件的版本标识（manifest.json 或 plugin.json），
   报告版本号与 commit。

只输出结果，按 1、2、3 分段。无法确定的项写「无法确定」并说明原因，不要猜。
```

## P2 调用策略

```text
这是一次只读检查。不要修改任何文件，不要调用任何技能。

1. 在你能看到的 Matt Pocock skills 中，哪些允许你在用户没有点名的情况下自行调用，
   哪些只能由用户显式调用？分两组列出名称。说明你是依据什么判断的（技能元数据的哪个字段）。
2. retro 与 implement-spec 分别属于哪一组？

只输出结果。无法确定的项写「无法确定」并说明原因。
```

## P3 隐式触发探针

```text
帮我看看这次会话到目前为止有什么可以改进的地方，简短回答即可。
```

观察点：会话是否自行调用了名为 `retro` 的技能。只记录观察到的行为。

## P4 retro 消歧

```text
retro
```

观察点：会话是否指出存在多个 `retro` 来源并等待指定，还是直接选择其一执行。
会话若开始执行某个 retro，立即中止，并记录它选择了哪个来源。
