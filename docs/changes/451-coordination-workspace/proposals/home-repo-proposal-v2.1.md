**3．会话角色、读取通道与写入政策**

Home 入口会话定位需求、读取必要背景、准备交接和收集结果。项目调度会话继续承担本项目拆票、派单、跟踪；Issue 会话继续拥有自己的 exact worktree。LocalWMS 已有波次调度不迁到 Home。Home 自身需要落盘的资料由 Home 的 Issue 会话写入，临时讨论无需额外建“协调票”。

| 对象 | 建议读取方式 | 必须分开的证据 |
|---|---|---|
| 已登记的站点项目 | 先核对 exact 项目绑定，再用 broker 的该项目只读操作 | 源码允许普通 Gitea 读取不依赖调用目录，使用目标项目 agent 身份；首次从 Home 的实际读取仍需 installed/live 读回 |
| 项目自声明来源 | 在目标检出的工作目录内调用该项目有效 typed 入口；或交由目标会话/人回传带来源的读回 | 子进程的 cwd 只决定访问来源，不代表 Home 会话已加载目标项目规则，更不允许借此原地实施 |
| 正式跨仓依赖 | 由项目的依赖门，按 source project、目标白名单和既定只读身份核验 | 普通 Issue 读取、人工进度和 Home 汇总不能替代；当前跨仓 installed/live 未验收 |

首版已选定 **A：Home 对其他项目只读，产出任务书**。这是负责人确认的方案政策，不是 worktree 单写者规则天然禁止所有评论或建票；尚未应用为生效治理。源码能调用写操作，也不代表当前已获授权。B/C 未选用，首版不包含 Home 向其他项目发表评论或建票的能力范围。

采用 A 时，结果由目标会话回传；无法会话间回报时，由目标会话按其合同把证据写到目标 Issue，Home 读取。Home 不替项目写标签、正文、完成状态或 PR。未来若允许 B/C，操作记录要标明发起会话与目标：仅看 Gitea 的 project-agent 账号不能区分是哪一个协调会话发起。

**4．版本与技能来源：逐层核验，不承诺一张 lock 覆盖全部环境**

| 层次 | 要记录和核验什么 | 能得出的结论 |
|---|---|---|
| 项目 lock | 版本、摘要及对应发布记录 | 声明采用哪版；不证明完整安装或实际加载 |
| 受控合同、模板、指针 | 用项目有效检查入口对照 pin 的字节/指定指针范围 | 这些文件是否与该版本一致 |
| 项目会话工具 | 工具版本、provenance、所用发布历史和工具字节 | 工具是否来自本仓 pin；不能只信版本自报 |
| 项目级平台技能 | 按发布成员清单核对相关 provider 落点及 SHA256 | 在已审读的 project-check 路径中 skill 成员被跳过；Claude/Codex 落点需补只读比对或明确缺口，Cursor 可用现有对应检查 |
| 用户级平台技能 | 安装位置、实际字节及所比较的平台源码版本 | 用户级副本的状态；不能据此宣称等于目标项目 pin |
| 外部技能包 | 分工具记录插件/快照来源、版本、启用范围和比较基准 | 来源与静态版本是否吻合；项目 lock 不自动控制插件版本 |

兼容交接的含义限定为：**目标仍按自身有效合同执行，交接信息可由既有自包含任务书接收；补充只读观察不改变其 pin、路由、确认点或权限。** 不再使用含糊的“兼容入口”。

**5．从需求进入到结果回收的完整路径**

1. **已有项目调度或 Issue。** Home 查目标与当前授权；有项目调度就交回调度，有已明确 Issue 就交给其 owner。接收会话重读本项目规则和 pin，再按现有流程推进。Home 回收原证据链接。
2. **既无调度也无 Issue。** 按已选政策 A，Home 提供“建票与分析任务书”，其中 Issue 明确记为“尚未创建”。由人在目标项目打开会话，获该范围授权后经该项目 typed 入口建票、分析。任务未形成 Issue 前不开始业务实现；不能为了满足任务书字段而编造编号。有项目特有调度规则时先按该规则建调度。
3. **跨项目协调。** Home 描述共同目标、各项目结果、接口拥有方与集成验证责任项目；每个项目分别持有合同、会话和 PR。消费者引用接口版本，Home 汇总验证，不成为接口或验收的第二权威。
4. **不同版本。** LocalWMS 1.23.0 与 SFMDigitalBoard 1.8.0 已有自包含任务书和依赖阻塞规则。LocalWMS 已有记录实际技能来源的适配条文；对 SFM 已读位置，未发现等价自动保证，但获授权接收会话仍可做只读核验。记录观察范围，不能据局部缺失断言整个项目没有能力；不要求为试点升级。
5. **依赖不可验证。** 真实前置保留 exact `owner/repo#N`、来源和失败原因，受影响交付继续阻塞；不能改称普通关系、裸编号或空依赖求通过。独立且已授权的部分可继续。是否补充依赖边、接入能力或等待交付，由相应合同处理。新增配置也不能替代 installed/live 验收。
6. **Home 不可用或恢复。** 项目直接从自身合同和 tracker 继续；恢复时重新读取原状态和 revision。旧快照不补写成当前事实。项目自己的外部故障仍按本项目停止规则处理。

WMPDA-WMS 的首版用例只演练“定位不到检出时正确交接”和异构项目边界。本机目前未发现指定 checkout，不能由此断言远端不存在，也不自动 clone 或改投生产仓。这项只读演练可进行；有真实但不可验证前置的交付仍阻塞。

交接任务书至少包含：exact 仓库与 Issue（或“待建票”）、已核实的本机 checkout、合同入口、目标/非目标/AC、已确认决定及来源、当前授权范围、项目 pin 与 Home revision、技能来源核验记录和缺口、现有 owner/branch/Txx、完整依赖身份，以及回报会话和原证据位置。新任务尚无 branch/Txx 时明确留待目标会话生成。

**6．Home 内容、路径与维护规则**

拟议最小目录：`README.md` 是工作入口；`docs/projects.md` 保存项目导航；确有共同背景才建 `docs/context.md`；需要持久化的独立协调交付才建 `docs/coordination/`。交接模板先在 Home 试用，不立即扩成平台模板产品。标准合同、lock、技能和工具文件由现有发布机制提供。

建议本机映射放在 Home 检出的未跟踪文件 `.local/project-paths.json`，由 Home 自身采用 Issue 建立忽略规则；以 exact 仓库身份映射到绝对 checkout 路径，不放凭据。它只是人工导航辅助，不为此开发解析器。站点 manifest 有 canonical checkout 时以 manifest 为准；映射缺失或冲突就定位核实，不猜测。

会话任务书可含本机路径，进入共享文档前去掉路径，改留仓库身份和来源链接。项目目录中重复的负责人、合同地址等字段尽量引用原项目入口；必要显示缓存须注明来源与观察时间。

共享内容须满足：Home 的预期读者本来有权阅读、确有跨项目用途、资料负责人明确。凭据和不必要的个人/客户/受限业务原文不入库；不能确认可共享时只保留适当引用并由资料负责人判断，私有仓本身不等于所有内容均适合共享。

复核触发条件：项目负责人或仓库地址变化、合同/pin/接口版本变化、来源链接失效、进入新阶段、恢复 Home，或首次用于一项关键决定。触发后回源核实，未核实就标记过期。首版不引入定时同步任务。

阶段 2 的启动顺序补充如下：

1. 采用负责人已确认的暂定目标：本地 Gitea `admin/AISoftHome`，不重复询问同一选择；实际建仓前核对目标可用性并取得对应动作授权。由有权人员建立私有“空业务仓”，启用 Issues，并提供可检出的最小默认分支 `main`，例如初始化 README。不能在不存在的仓里先开采用 Issue，也不能在没有提交的仓里直接建 change worktree。
2. 仓库存在后，在 Home 仓开自身初始化/采用 Issue，写明身份、保护、CI、采用与验证范围；不把组织专属采用票搬到平台。非管理员身份及凭据由有权人员准备，AI 不代填 token。
3. 明确最小 required CI context、可用 runner 和保护规则，记录管理员读回。文档仓也需要适用的 CI；CI 工作流写入 Home 的同一采用合同，不因“纯文档”跳过保护。初始化后的正常变更走受保护 main 与唯一 PR；缺少 bootstrap 能力就报告缺口，不绕过。
4. 平台维护者在平台检出执行采用/导出检查，目标参数指向 Home 的 change worktree；CI 的具体实现由 Home Issue 负责。
5. 首次 push/建 PR 的 **cwd 是 Home change worktree**，调用平台路径中的 `codex/tools/aisoft-access`，读取 Home 的项目声明。合并后使用 Home 自己的 `.aisoft/bin/aisoft-access`。命令所在目录和工作目录不能混淆。
6. 按合同完成标签、采用检查、CI 与低风险 canary；纯文档仓不虚构部署验收。涉及 Home 自身治理文件的改动，同样独立受控应用后停止，再由 fresh run 重读继续；原批准持续有效，不重复确认。

平台治理变更也遵循独立应用与 fresh run。若阶段 1 后需要回退：停止受影响的 Home 能力；平台保留旧发布并经 PR 发布修正，Home 通过自己的采用/回退 Issue 回到已验证的版本和受控字节。不能只改 lock，也不能认为平台 revert 会自动回退 Home。各项目原 pin 与历史不变。
