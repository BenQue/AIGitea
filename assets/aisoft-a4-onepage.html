02 / 流程

一个 issue 的一生（九步 · 三道闸门）

人工闸门 AI 参与 确定性自动化
1
你
提 issue + needs-analysis
issue 号 N 贯穿分支、提交、PR、文档、部署记录。
2
VM Agent · 自动
15 分钟内自动分析
只读仓库 → 00-summary.md + 🤖评论 + 邮件。
闸门A
你
确认方向
对 → spec-drafting；防止朝错误方向做一整轮。
3
Mac · 你+AI
brainstorm → spec/plan
01-spec（可测验收标准）+ 02-plan → docs-only spec PR。
闸门B
你 · 最值钱的一道
合并 spec PR + approved
改意图比改代码便宜一个数量级；spec 成为 agent 无关的意图接口。
4
Mac · 你+AI
按 spec 实现（TDD）
npm test 全绿才开 code PR；执行体可插拔（Claude/Codex）。
5
act_runner · 自动
CI 检查（合并硬门）
安装→生成→空库迁移→测试→构建；不绿无法合并，任何人不能直推 main。
闸门C
你
审代码 · 点 Merge
spec+plan+diff 同仓库并排对照；合并即触发部署并自动关 issue。
6
act_runner · 无 AI
制品 → 部署 → 健康检查
停应用→迁移→切软链→启动→pm2 断言→/api/health；按 sha 留存可回滚；人工 promote 上生产（同一制品同样字节）。
